## 📖 User Guide

> 💡 **Placement & Path Selection Tips**:
> 1. **We strongly recommend placing `EFMI_Conflict_Auditor.exe` directly inside your `EFMI` root folder.** That way, every time you launch the program, it will automatically detect the current directory and scan immediately without needing to select a path each time.
> 2. If you manually browse for a folder, make sure to select the **`EFMI` root directory** (the parent folder that contains `Mods` and `ShaderFixes`), **NOT the `EFMI\Mods` subfolder**!

The workflow in the UI goes from top to bottom: once your `EFMI Path` is set, click **"🔍 Scan Now"**. For normal troubleshooting, there is no need to check *"Scan disabled Mods (DISABLED_ prefix)"*.

### 1. ⚠️ Risk Warnings & ⚡ ShaderCache Manager
- **⚠️ Risk Warnings (`ShaderFixes` Status)**:
  Alerts you whenever legacy anti-blur patches or custom shadow/outline shader replacement files exist inside the `ShaderFixes` folder. Because files in `ShaderFixes` globally replace low-level shaders across the entire game, they frequently cause missing body parts, discolored patches, or broken shading on characters.
  - **Fix**: Click the **"📂 Open Folder"** button on the right and **clear all files inside `ShaderFixes`**!
- **⚡ ShaderCache Manager (Cache Switch & Cleanup)**:
  - **Global Cache Detection & One-Click Toggle**: Inspects both `[Rendering] cache_shaders = 1` in `EFMI\d3dx.ini` and whether `ShaderCacheSettings.ini` inside `Mods` (including 2nd-level subfolders like `RabbitFX -ENDMI-`) has been moved out of `DISABLED`. Clicking **"⚡ Enable / ⏸ Disable"** manages `cache_shaders` cleanly in `d3dx.ini` and automatically moves any active `ShaderCacheSettings.ini` back into `DISABLED` to prevent duplicate-key warnings.
  - **🧹 One-Click Clear `ShaderCache`**: Corrupted shader cache files generated by conflicting Mods in `EFMI\ShaderCache` persist across `F10` reloads until deleted, causing broken textures to remain on screen. Click **"🧹 Clear"** to wipe `EFMI\ShaderCache` in one click before pressing `F10` in-game.

### 2. 🔥 Conflict Detection
The tool first classifies Mods by their **architecture ("process")**:
- `All Mod Types`
- `🦴 MergedSkeleton`
- `🔗 CrossIB`
- `📦 Simple Mod`
- `✨ FX Plugin` (Standalone shader/effect plugins such as `RabbitFX`, `CrossIBClassifier.ini`, `KatFXMatcap`, etc.)

#### Severity Levels (Highest to Lowest)
- 🔴 **`HIGH`**: **High conflict risk — requires immediate attention** (very likely to cause black models, broken textures, redundant global classifier clashes, or severe FPS drops).
- 🟠 **`WARNING`**: **Moderate risk** — commonly seen on `CrossIB` Mods or unique-ID `if_nz` tag-isolated `CutoutMask.ini` shaders; compatible in normal small-scale use unless stacked heavily or visual glitches occur.
- 🔵 **`INFO`**: **Low-risk notice** — used for compliant private-namespace classifiers (`namespace = ...`), same-character overlap checks, and Normal + Ultimate dual-form companion notices.

#### Four Detection Categories
- **`A. ShaderOverride Warnings`**:
  In XXMI / 3DMigoto, `[ShaderOverride]` has the highest global priority and acts like a hard shader hijack. If a Mod is flagged as **`HIGH`** in this category (e.g., overriding a shared shader with a custom private `filter_index`), it is very likely the root cause of other characters turning black or having scrambled textures. *(Note: Standard `CrossIB` pass markers `200~205` and standard `RabbitFX`-compatible `1718.1 / 1718.2` tags are automatically downgraded to `WARNING`).*
- **`B. ShaderRegex Warnings`**:
  Inspects `[ShaderRegex]` sections inside non-FX-Plugin character Mods:
  - Classifiers using a **private `namespace`** without shared `filter_index` (e.g. `SlotClassifier.ini`) are recognized as compliant **`INFO`** notices (do NOT delete them);
  - Bytecode injections isolated via **private `namespace` + unique constant ID `if_nz` guards** (e.g. standalone `CutoutMask.ini`) are graded **`WARNING`**;
  - Unisolated character-bundled `[ShaderRegex]` sections remain **`HIGH`**.
- **`C. Duplicate ShaderRegex`**:
  Distinguishes three patterns accurately:
  1. **Duplicate shared `filter_index` (`HIGH`)**: Pinpoints redundant non-namespaced classifier copies inside character folders that duplicate root shared plugins (`CrossIBClassifier.ini` / `RabbitFX`) and can be safely deleted;
  2. **Private-namespace template reuse (`INFO`) & unique-tag-isolated `Pattern.Replace` stacking (`WARNING`)**: Explicitly warns NOT to delete internal private classifiers or `CutoutMask.ini` files (escalates to `HIGH` only on tag ID collisions, unguarded replacements, or heavy stacking across ≥6 Mods);
  3. **Incompatible FX plugins (`HIGH`)**: Alerts you when conflicting FX plugins (such as `KatFXMatcap` and `RabbitFX`) are enabled together.
- **`D. Duplicate Active Character`**:
  Assigned the lowest **`INFO`** severity level. Active only when scanning **enabled** Mods, preventing accidental multi-skin overlaps on the same character. Automatically recognizes **Normal + Ultimate (`Ultimate / ult / henshin`)** dual-form companion packages and advises keeping both enabled; for other overlaps, judge whether they belong to the same character.

### 3. 🛠️ Conflict Details & Code Inspector
- Click any item on the left to inspect its root-cause analysis, troubleshooting advice, all involved `.ini` files with exact line numbers, and a live INI section code preview.
- **📝 Open INI**: Opens the `.ini` file directly in your default Windows editor (VS Code, Notepad++, Notepad, etc.).
- **📂 Reveal in Explorer**: Highlights the `.ini` file directly in Windows File Explorer.

### 4. 📄 Export Report & AI-Assisted Analysis
- **Local Report Saving**: Check **"Auto-save TXT Report"** or click **"📄 Export Report"** to save a full plain-text audit report (`EFMI_Conflict_Report_xxxxxx.txt`) directly inside your local `EFMI` root folder.
- **Feed to AI Assistants**: The exported `.txt` report contains structured details of every flagged Mod, exact `.ini` file paths, line numbers, shader hashes, and `filter_index` values. You can feed this `.txt` file directly to any **AI assistant** (ChatGPT, Claude, Gemini, DeepSeek, etc.) for deeper diagnosis or automated `.ini` fix instructions!

## 🔒 Safety Guarantee & Build from Source

- **100% Non-Destructive to Character Mods**: Conflict scanning is strictly read-only and **never modifies, renames, or deletes any character Mod files** (files are only touched when you explicitly click the ShaderCache toggle or clear buttons to update `d3dx.ini`, tuck `ShaderCacheSettings.ini` into `DISABLED`, or clear temporary cached shaders in `ShaderCache`).
- **Zero-Dependency Single-File Build**: Built on native Windows `.NET Framework 4.8` (WPF) — runs out of the box on any Windows 10 / 11 PC:

```powershell
dotnet build EFMI_Conflict_Auditor.csproj -c Release
```

Compiled binary path: `bin\Release\net48\EFMI_Conflict_Auditor.exe`
